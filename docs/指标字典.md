# 指标字典（Metrics Dictionary）

> 作用：统一口径，避免"同名不同义"。所有指标均由 `sql/02_ads_metrics.sql` 计算，
> 关键口径配有 `ads_stage_validation` 自动校验，禁止在代码里重复实现业务口径。

## 一、口径定义

| 指标 | 口径定义 | 计算方式 | 数据来源 |
| --- | --- | --- | --- |
| 学习时长 total_time | 学生累计有效学习时长（分钟） | ODS 原值，不做平滑 | student_learning_summary |
| 交互次数 study_count | 学生累计学习交互次数（次） | ODS 原值 | student_learning_summary |
| 单次学习时长 | 平均每次交互的时长（分钟/次） | `total_time / NULLIF(study_count, 0)` | SQL 派生 |
| 学习强度分层 | 按累计学习时长的四档划分：轻度 **≤10 分钟**、中度 **≤60 分钟**、深度 **≤300 分钟**、沉浸 **>300 分钟** | `CASE WHEN` 分档，**上界含端点** | SQL 派生 |
| 分层人数占比 | 该层人数 / 全体学生数 | `COUNT(*) / SUM(COUNT(*))` | SQL 派生 |
| 时段活跃量 | 该小时的学习交互次数 | ODS 原值 | hour_activity_summary |
| 时段活跃占比 | 该小时活跃量 / 全天活跃量 | `active_count / SUM(active_count)` | SQL 派生 |
| 高风险学生 | 规则口径：`total_time < 40 分钟` **或** `study_count < 15 次` | 布尔规则，非模型输出 | 业务规则 |
| 单次学习质量偏低 | 单次学习时长低于全体中位数 | `avg_minutes_per_action < MEDIAN` | 派生目标 |

## 二、分析口径（统计学指标）

| 指标 | 含义 | 实现 | 当前值 |
| --- | --- | --- | --- |
| 均值 / 中位数 | 集中趋势；两者差距反映长尾程度 | pandas | 1,086.8 / 256.7 分钟 |
| P90 分位 | 头部学生水平 | `quantile(0.9)` | 3,385.8 分钟 |
| 基尼系数 | 学习投入分配的不均衡度（0 完全平均，1 完全集中） | 排序后累加公式 | 0.7274 |
| 帕累托贡献 | 头部 N% 学生的时长贡献占比 | 窗口函数累计占比 | Top 10% → 53.7% |
| 相关系数 | 两个核心指标的线性/秩相关，用于共线性诊断 | Pearson / Spearman | 0.9757 / 0.9865 |
| AUC | 模型排序能力（与阈值无关） | sklearn `roc_auc_score` | LR 0.9889 / RF 0.9366 |
| 召回率 Recall | 真实风险学生中识别出的比例（**预警场景主指标**） | sklearn `recall_score` | LR 0.9859 / RF 0.5694 |

## 三、口径治理规则

1. **端点归属必须写清**：`0-10 分钟` 档默认包含 10 分钟端点（本数据集上按 `<10` 实现会误分 3 人）。
2. **口径变更需留痕**：修改分档边界时同步更新本字典 + `sql/02_ads_metrics.sql` 注释，并跑 `ads_stage_validation`。
3. **口径只有一处实现**：报表层只允许引用 ADS 表，禁止在 BI/前端里再用 `CASE WHEN` 重写分档。
4. **均值不单独对外**：偏态分布下均值必须与中位数、分层占比同时出现，避免误导决策。

## 四、指标复用建议（新增分析时优先使用）

- 人群分层 → `ads_student_profile`（已含分层标签、排名、分位、累计占比）
- 分层汇总 → `ads_stage_structure`（人数/占比/人均/中位数）
- 集中度分析 → `ads_concentration`（Top 1% / 5% / 10% / 20%）
- 时段分析 → `ads_hour_distribution`（占比/排名/累计占比/环比）
- 口径校验 → `ads_stage_validation`
